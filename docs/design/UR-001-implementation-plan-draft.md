## 3. Порядок и почему

**Рекомендация: реестр первым (P1→P2), затем оболочки, затем модули.**

- Реестр — позвоночник: скилл, проверка репозитория и статус изменений читают его; без него модули — разрозненные скрипты (архитектура §1, §6).
- Критерий готовности UR-001 №2 (схема + пример v1, проходящий валидацию) закрывается уже в P1.
- P2 идёт до 28.09: к активации Alpenglow журнал уже в devnet, смена статуса видна через реестр — сильный момент для демо.

**Альтернатива (ранее предложено владельцем): rent первым.** Плюс — самостоятельный, наглядный, цифры уже есть. Минус — не двигает пункты 1–3, 5, 6 минимума; при сдвиге сроков остаёмся со сканером без реестра, т.е. без ядра идеи. Компромисс, если владелец настаивает: P1 (4 дня) → P4a → P2.

1. **git** — решено 2026-09-18: приватный репозиторий `mskrad/Epochnotes`, инструкции в `.gitignore`. Лицензия — MIT (решено 2026-09-18). Открыто: момент открытия репозитория — к подаче на хакатон.
2. **Порядок этапов** — решено 2026-09-18: реестр первым (§3).
3. **Таймбокс Anchor-программы и фолбэк** — решено 2026-09-18: фолбэк согласован. Офчейн-подписанный журнал (ed25519 + Merkle + `prev_root`) делается отдельной задачей до программы (UR-005), поэтому фолбэк — уже готовый результат, а не аварийная работа; программа — UR-006 с таймбоксом 3 дня.
4. **Хранение содержимого версий**: GitHub raw по хеш-адресуемому пути (`registry/versions/<merkle_root>.jsonl`) + проверка sha256 на клиенте; Irys — позже через код зеркал VRE. Рекомендация: GitHub к 12.10.
5. **Формат записи**: источник — YAML; каноническая форма — JSON по RFC 8785 (JCS), лист = sha256(JCS). Схема — zod с генерацией JSON Schema. Рекомендация: да.
6. **Переиспользование VRE**: npm-зависимость `verifiable-outcome-sdk` (Merkle по паре `sha256_pair_v1`, чтение по URI) против копии ~90 строк с указанием источника. Рекомендация: зависимость; при конфликте сборки — копия. Хеш листа — наш (одиночный sha256 JCS), не `sha256d_jsonl_v1` VRE.
7. **Ключ издателя**: отдельный keypair для devnet (не `~/.config/solana/id.json`), хранится вне репозитория.
8. **Протоколы для возврата rent (P4a)**: какие 2–3? Нужен путь закрытия аккаунта пользователем — кандидаты по замеру: Raydium CLMM (позиции), Drift (пользовательские аккаунты), OpenBook v2 (открытые ордера). Требует проверки инструкций каждой программы.
